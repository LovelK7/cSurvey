# Exports, Printing and Preview

## Purpose

This subsystem is how a finished cave map (and its survey data) leaves cSurvey: as Therion source files (`.th` centerline + `.th2` scraps + `.thconfig`), as SVG, as raster images (JPG/PNG/TIF/BMP), on paper via GDI+ printing, as Google Earth KML, Excel `.xlsx`, VisualTopo `.TRO`, or as a Loch 3D model (`.lox`, produced by running the external `therion.exe`). It also covers the print/export preview window (`frmPreview`) and the small `cPrintController` helper project. Everything of substance is in the `modExport` module (`cSurveyPC/modExport.vb`, 4104 lines) plus `modSVG`/`modMetapost`; the forms are thin option-collectors around it.

## Domain concepts

- **Therion vocabulary**: a `.th` file contains nested `survey` blocks with `centerline … endcenterline` shot data; a `.th2` file contains `scrap … endscrap` blocks of 2D drawing primitives (`point`, `line`, `area`); a `.thconfig` file tells `therion.exe` what to compile (`source` lines + `export` commands). Profile view is Therion's "extended" projection. cSurvey generates all three.
- **Station qualification**: Therion station names are qualified per sub-survey as `name@survey.path`. cSurvey emits one Therion sub-survey per cave/branch and tracks in which branch each station first appeared (`TrigpointFirstSession` dictionary); stations reused across branches get `equate` lines (cSurveyPC/modExport.vb:3891).
- **Name dictionary**: an optional `IDictionary(Of String,String)` passed to every data exporter that renames stations on the way out. Two producers: `TherionGetSavenameDictionary` (sanitizes names, cSurveyPC/modExport.vb:3132) for user-facing exports, and `CreateStationDictionary` (numeric indexes, cSurveyPC/modExport.vb:26) for internal therion runs ("safe names", setting `therion.trigpointsafename`).
- **Scrap export vs sketch export**: `TherionExportOptionsEnum.Scrap` converts the *cSurvey drawing* (plan/profile items) into `.th2` scraps; `ExportSketch` exports imported *raster sketches* (`cDesignSketch`, e.g. from TopoDroid) as `.th2` scraps with a `-sketch image.jpg` background (cSurveyPC/modExport.vb:3919).
- **Export profile / preview profile**: named, per-design bundles of rendering options. `cExportProfile` wraps a `cOptionsExport` (image size, unit, DPI, margins, scale, file format, SVG options) and is persisted inside the `.csx` XML under `exportprofiles` (cSurveyPC/cExportProfile.vb:12). The two system profiles are the survey options named `_export.plan` / `_export.profile` (cSurveyPC/cExportProfile.vb:30). The print side uses the analogous `_preview.plan` / `_preview.profile` options.
- **therion.ini / THERION env var**: cSurvey drives `therion.exe` with the environment variable `THERION` pointing at a folder containing `therion.ini` (cSurveyPC/modMain.vb:379); the ini is regenerated by cSurvey from user settings, it is not hand-edited (see below).

## Architecture

Two largely independent halves:

**1. Data/file exporters (headless-capable).** `modExport` is a VB module of pure `Sub Export(Survey, Filename, Options)` functions that read the loaded `cSurvey` object (segments, sessions, trigpoints, calculated coordinates, designs) and write text/XML/XLSX files. No form state is consumed; the WinForms dialogs (`frmExportTherion`, `frmExportExcel`, `frmExportGoogleKML`) only load/save checkbox defaults into application settings and are read once by the caller in `frmMain2.pSurveyExport` (cSurveyPC/frmMain2.vb:5662), which builds an `…OptionsEnum` flags value and calls the module function. (`frmExportVisualTopo` and `frmExportHolos` exist as files but are never instantiated — dead code; VisualTopo export runs with `VTopoExportOptionsEnum.Default` and no dialog, cSurveyPC/frmMain2.vb:5678-5679.)

**2. Rendering exporters (image/SVG/print) hosted by `frmPreview`.** The same design-paint engine used on screen (`cDesign.Paint(Graphics, cOptionsCenterline, …)`, see [rendering-and-plot.md](rendering-and-plot.md)) is pointed at three different `Graphics` targets: an offscreen `Bitmap` for image export (cSurveyPC/frmPreview.vb:976), the printer `Graphics` inside a `PrintDocument.PrintPage` handler (cSurveyPC/frmPreview.vb:1095), or — for SVG — bypassed entirely in favour of `cDesign.ToSvg(...)` which walks the same item tree and emits XML (cSurveyPC/cDesignPlan.vb:444).

**Data flow for a Therion export** (the flagship path): `frmMain2.pSurveyExport` → `modExport.TherionThExportTo(Survey, file.th, dictionary, options)` (cSurveyPC/modExport.vb:3791) writes the `.th` master file; while writing, per option flags it also spawns sibling files: `*.th2` scrap files per cave/branch/projection (`pTherionExportToScraps`, cSurveyPC/modExport.vb:2393), sketch `.th2` + `.jpg` pairs (cSurveyPC/modExport.vb:3923), a surface-elevation file (cSurveyPC/modExport.vb:3819) and a `*_thconfig.thconfig` layout file with metapost clipart definitions (`pTherionExportMapConfig`, cSurveyPC/modExport.vb:2863); every generated `.th2`/surface file gets an `input "file"` line in the master `.th`, and all paths are returned in `cTherionCalculateResult.Files` (cSurveyPC/modExport.vb:3768). Optionally `TherionCreateConfig` (cSurveyPC/modExport.vb:799) writes a `.thconfig` whose `export map -proj plan/extended -output *.pdf` commands make `therion.exe` produce the final PDF — **cSurvey itself has no PDF writer**.

The same exporter is reused *internally* in three places that then run `therion.exe` (`modMain.ExecuteTherion`, cSurveyPC/modMain.vb:363): the calculation engine (loop closure: exports temp `.th`, config with `export model -fmt compass` + two `.xvi` maps, parses the log for declination/loop errors — cSurveyPC/Calculate/cCalculate.vb:1663-1688), the Loch 3D viewer/`.lox` export (cSurveyPC/frmMain2.vb:9745), and `pSurveyExportToTherion(Commands)` (cSurveyPC/frmMain2.vb:9674) — the "TherionPad" ribbon buttons that compile the survey to a **finished** map/model in one click: temp `.th` with the `Scrap` flag (drawings included, frmMain2.vb:9713), `TherionCreateConfig` with the given export command (:9715), `ExecuteTherion` (:9718). Commands used: `export map -proj plan -fmt pdf|svg|dxf` (btnTherionPadExportPlan, frmMain2.vb:9953-9971), `export map -proj extended …` (btnTherionPadExportProfile, :9977-9995), `export model -fmt loch|compass|survex|dxf|esri|vrlm|3dmf|kml` (btnTherionPadExport3D, :9919-9947).

### The Therion export in depth

**Encoding / UTF-8 handling.** All therion-family files are written with `TextFileEncoder = New UTF8Encoding(False)` — UTF-8 *without BOM* (cSurveyPC/modExport.vb:3371) — and start with an `encoding utf-8` directive generated from the encoder's WebName (cSurveyPC/modExport.vb:3373). Identifiers (survey names, scrap names, file names) pass through `FormatTextFor(text, BaseWithoutSpacesAndSlash)` which first calls `.Unidecode()` (Unidecode.NET) then `UnAccent`/`RemoveDiacritics` and strips punctuation (cSurveyPC/modExport.vb:3074-3118). The `.Unidecode()` transliteration was added by commit `0b90671` to fix crashes/invalid files when the survey name contains non-Latin UTF-8 characters; commit `0b90671` also made splay-station filtering in scraps consistent. Free text (titles, labels) instead uses `FormatTextForEnum.TherionText`: kept as UTF-8, CRLF→`<br>`, quotes doubled, wrapped in `"…"` (cSurveyPC/modExport.vb:3119).

**Survey data mapping** (`pTherionThExportToCaveBranch`, cSurveyPC/modExport.vb:3404). One nested `survey <branch>` block per cave/branch (recursion at :3688); inside it one `centerline` per session containing: `date` (:3419), `vthreshold` (:3423), declination logic depending on GPS/nord-correction mode (:3425-3465), `units length/compass/clino` + `data normal from to compass clino length left right up down` (or `data diving`/`data cartesian`, :3467-3497), `calibrate` lines (:3474), `grade` (:3499). Every shot row emits a `flags` line (:3622-3628; the emit-only-on-change check is commented out): `splay`, `duplicate`, `surface`; generic *exclude* is smuggled out as `surface` because Therion has no generic exclusion (:3626). It is followed by the measured values with LRUD (:3645). With `SegmentForceDirection`, every non-splay shot also emits `extend left/right/vertical from to` (:3653-3676). After all branches, a global `centerline` emits `extend start origin@…` (:3844), `mark … fixed/painted/temporary` (:3866), `extend ignore` for user-broken connections (:3873), `fix` with lat/long when `GPS.SendToTherion` (:3880), entrance `station … entrance` lines (:3888) and cross-branch `equate`s (:3894).

**Splays without names (commit `7a7fe49`).** Flag `TherionExportOptionsEnum.SegmentSplayWithoutName = &H8000` (cSurveyPC/modExport.vb:669). When set, a splay shot's *to* station is replaced by `"."` (anonymous splay) at cSurveyPC/modExport.vb:3618-3621 (and :3537-3541 on the oversampled path), and splay-named stations are excluded from scrap `point … station` lists (cSurveyPC/modExport.vb:2448). The UI checkbox is `chkExportSplayWithoutNames` in `frmExportTherion` (persisted as setting `data.export.therion.splaywithoutname`, cSurveyPC/frmExportTherion.vb:6) and mapped to the flag at cSurveyPC/frmMain2.vb:5688. Independently, `CalculateSplay` controls whether the `splay` flag is emitted at all (:3622).

**Drawing → `.th2` mapping** (`pTherionExportToScraps`, cSurveyPC/modExport.vb:2393). One scrap file per cave × branch × projection, named `<file>_<plan|extended>_<cave>[_<branch>].th2` (:2437). Coordinates: drawing points are Y-negated and scaled ×4 (`pTherionGetPoint`, :2260, `sScale = 4` at :2444). Content:
- station reference points `point x y station -name N@survey` for every branch station (:2457);
- `cItemFreeHandLine/Area/InvertedFreeHandArea` → `line <type>` blocks; splines are first converted to beziers (`modPaint.ToBezier`, :2475) and written as bezier control triplets (:2490-2505); line type comes from the item's pen via `GetTherionLineType` (:2324): CavePen→`wall`, GenericPen/Gradient→`contour`, Cliff→`floor-step`, Overhang→`overhang`, pen None→`border:invisible`, rock/concretion category→`rock-border`/`rock-edge`; `-reverse on` for "down" pens (:2293); inverted areas get `-outline out/in` (:2361);
- closed `FreeHandArea` items additionally emit `area <type> … endarea` referencing the line ids (:2526-2534), area type from the brush via `GetTherionAreaType` (:2274): water/sand/debris/blocks/flowstone/pebbles/else bedrock;
- `Clipart` and unknown `Sign` items → `point … u:<name>` user symbols with `-attr scale/rotate` (:2535-2563); the corresponding Metapost `def` code is generated into the layout by `modMetapost.ClipartToMetapost` (cSurveyPC/modMetapost.vb:102) inside `pTherionExportMapConfig` (:2876-2884); known signs map to native Therion point types via the big `GetTherionSign` switch (:2635);
- `Text` items → `point … label -text "…"` with align/scale options (:2573-2581);
- the file carries xtherion editor hints `##XTHERION## xth_me_area_adjust …` and a `scrap <name> -projection plan|extended` header (:2619-2623).

`pTherionExportMapConfig` (:2863) also writes `<file>_thconfig.thconfig`: `source`, a `layout defaultlayout` containing all metapost cliparts, `scale 1 250`, legend/statistics switches, and two `export map … .pdf` commands (:2897).

**therion.ini.** `cTherionINISettings` (cSurveyPC/cUIHelpers.vb:4232) is a key/value list edited in `frmSettings`, serialized to the app setting `therion.inisettings`, and materialized as `<userAppPath>/therion.ini` by `Invalidate()` (cSurveyPC/cUIHelpers.vb:4253); if the user didn't set `loop-closure`, it appends `loop-closure therion` (:4270). When running `therion.exe`, `ExecuteTherion` sets env var `THERION` to that folder (or to setting `therion.inipath` if set) so therion picks the ini up (cSurveyPC/modMain.vb:379-383; call sites cSurveyPC/frmMain2.vb:9717, cSurveyPC/Calculate/cCalculate.vb:1687). The `cSurveyPC/therion.ini` file in the repo is an empty placeholder shipped with the app. So therion.ini configures *therion's* behaviour (notably loop-closure method) for the runs cSurvey launches — it does not configure the export text itself.

### Print / preview pipeline

`frmPreview` (cSurveyPC/frmPreview.vb:18) has three modes (`PreviewModeEnum`, :46): `Preview` (printing, opened from frmMain2.vb:5776), `Export` (image/SVG, frmMain2.vb:5751), `Viewer` (read-only map). Left nav lists the plan/profile *profiles*; the side panel edits the current `cOptionsPreview`/`cOptionsExport` and every checkbox triggers a re-render.

Printing is a plain WinForms `PrintDocument` (`oDoc`, created at frmPreview.vb:292). **`cPrintController`'s role**: the C# project contains only (a) `PrintControllerNoStatusDialog`, a `PrintController` wrapper that suppresses the modal ".NET printing page N" status dialog (cPrintController/cPrintController.cs:22), installed on `oDoc` at frmPreview.vb:294, and (b) a re-implementation of `PrintPreviewControl` (cPrintController/cPrintController.cs:204) used as the on-screen preview surface (`pPreview`, cSurveyPC/frmPreview.Designer.vb:116) — it renders preview pages by printing into a `PreviewPrintController` (cPrintController.cs:399). It is UI plumbing, not a rendering engine.

Page layout: the printer combo is filled from `PrinterSettings.InstalledPrinters` (frmPreview.vb:336) and the page-format combo from the selected printer's `PaperSizes` (frmPreview.vb:346). For *image* export the page size presets instead come from `papersizes.xml` via the `frmParametersPageSize` flyout, which just writes `ImageWidth/ImageHeight/ImageUnit` into the `cOptionsExport` (cSurveyPC/frmParametersPageSize.vb:26-59); margins are edited live by `frmPreviewMargins` mutating the shared `cMargins` (cSurveyPC/frmPreviewMargins.vb:38).

**There is no multi-page atlas.** `oDoc_PrintPage` never sets `e.HasMorePages` (no occurrence in the codebase), so a print job is always a single sheet: the design is either fit-to-page or drawn at a fixed 1:N scale (`modPaint.GetZoomFactor` converts scale to printer units, frmPreview.vb:1141-1171), centered via a `Matrix` (frmPreview.vb:1178), then `Survey.Plan/Profile.Paint` plus the Compass/Scale/InfoBox gadgets are drawn (frmPreview.vb:1184-1212). **PDF export is not direct**: users print to a PDF printer driver (the code even forces the legacy Win11 print dialog via registry, frmPreview.vb:1223) or let Therion produce PDFs from the exported `.th/.th2/.thconfig`.

### SVG export specifics

Output document (built by `modSVG.CreateSVG`, cSurveyPC/modSVG.vb:239): `<svg width="Wunit" height="Hunit" viewBox="x y w h">` where the viewBox is the page rectangle converted to **meters** (1 SVG user unit = 1 m of cave; conversion `ConvertRectangleToMeters`, cSurveyPC/modSVG.vb:172, assumes 96 dpi for px) and back-translated so cave coordinates land on the page (frmPreview.vb:1626-1630). Namespaces: svg, xlink, `csurvey` (`http://www.csurvey.it`), plus sodipodi/inkscape when `AddInkscapeReference` (modSVG.vb:251-259). A `<defs>` element is always first (modSVG.vb:262).

Structure: if scale bar/compass/info-box are enabled, the drawing goes into a nested `<svg id="plan">` with its own viewBox and the gadgets into a sibling `<svg id="legacyobjects">` (cSurveyPC/cDesignPlan.vb:453-491); otherwise a single Inkscape layer `<g id="plan" inkscape:groupmode="layer">` (modSVG.vb:284). Inside, `ToSvgItem` creates a layer `g id="plandesign"` and appends one `<path>` (or `<text>`/`<image>`) per drawn item; the centerline plot is appended when `DrawPlot` is on (cSurveyPC/cDesignPlan.vb:475).

Option flags (`cSVGWriter.SVGOptionsEnum`, cSurveyPC/modSVG.vb:14): `UseStyles` dedupes brush/pen combinations into CSS classes emitted in a `<style>` block (`AppendStyles`, modSVG.vb:74; `GetItemStyle`, modSVG.vb:555); `ReuseClipart` puts clipart geometry in `<defs>` and references it with `<use>` (modSVG.vb:433, 62); `AddSourceReference` stamps each element with `csurvey:type/category/cave/branch` attributes so the SVG can be round-tripped back (modSVG.vb:227); `TextAsPath`, `Images`, `Clipping`, `ClipartBrushes` control fidelity. The flags are assembled in `frmPreview.pExport` from application settings `svg.*` (frmPreview.vb:1637-1660); per-profile `UseStyles`/`ReuseClipart` also live in `cSVGOptions` persisted in the file (cSurveyPC/cOptions.cMargins.vb:8). `frmPreviewSVGOptions` itself is a nearly empty flyout stub holding a `cSVGOptions` (cSurveyPC/frmPreviewSVGOptions.vb:4); the designer-bound controls edit it (inferred — no logic in the .vb). Output is written UTF-8, non-indented, via `XmlWriter` (frmPreview.vb:1670-1675).

## Key flows

### 1. Export Therion `.th` + drawings from the UI

1. cSurveyPC/frmMain2.vb:5670 — user picks `.TH` in the save dialog inside `pSurveyExport(ImportExportFormatEnum.Survey)`.
2. cSurveyPC/frmMain2.vb:5681-5689 — `frmExportTherion` shown; flags assembled: `SegmentForceDirection`/`SegmentForcePath` from settings, `Scrap` if "export design" checked, `SegmentSplayWithoutName` if checked, always `CalculateSplay`.
3. cSurveyPC/modExport.vb:3132 — `TherionGetSavenameDictionary` builds the station rename map (sanitized names).
4. cSurveyPC/modExport.vb:3799-3803 — `TherionThExportTo` opens the file with BOM-less UTF-8, writes `encoding utf-8`, `#csurvey <version>`, and `survey <unidecoded-name> -title "…"`.

## How to modify safely

- **Keep the encoding contract**: every therion-family writer must (a) use `modExport.TextFileEncoder` (BOM-less UTF-8) and (b) emit `pGetTherionTextEncorderDef` as the first line (cSurveyPC/modExport.vb:3371-3375). Therion rejects files whose declared encoding disagrees with the bytes; a BOM breaks the `encoding` directive parser.
- **Identifiers vs text**: anything that becomes a therion *identifier* (survey names, scrap names, station names) must go through `FormatTextFor` with a `Base*` mode or the station dictionary; anything human-readable through `TherionText`/`TherionFile` (quoted). Mixing these up reintroduces the pre-`0b90671` UTF-8 bug.
- **`TherionThExportTo` is shared infrastructure**: the calculation engine (cSurveyPC/Calculate/cCalculate.vb:1673), Loch export, XVI generation and the user-facing export all call it. Changing emitted syntax can silently break loop-closure calculation (the calc parses therion's log and maps errors back to segments by line number — cSurveyPC/Calculate/cCalculate.vb:1726). Prefer new `TherionExportOptionsEnum` flags (note `UseSubData` and `Oversample3D` currently share the value `&H1000000`, cSurveyPC/modExport.vb:676-677).
- **`TrigpointFirstSession` bookkeeping** must stay exactly in sync between the shot writer and everything that later qualifies station names (`equate`, scrap `point station`, sketch stations, `extend start`); a station qualified with the wrong sub-survey produces therion "station not found" errors.
- **frmPreview render parity**: `pDrawExportPreview`, `oDoc_PrintPage` and the SVG branch each duplicate the fit/scale/translate math. If you change one (e.g. margins handling), change all three, or extract it — otherwise the preview will not match the printed/exported output.
- **Options persistence**: `cOptionsExport.SaveTo/Import` writes into the `.csx` XML; new properties need both directions plus defaults in both constructors (cSurveyPC/cOptionsExport.vb:161, 189, 205, 237) or old files will load with zeros (see the existing `ImageWidth = 0 → 4096` fallback :212).
- Exporters assume the survey is **already calculated** (they read `Survey.Calculate.TrigPoints(...)` — e.g. cSurveyPC/modExport.vb:2450); when driving headlessly, run the calculation first (see [calculation-engine.md](calculation-engine.md)).

## Gotchas

- **`cTherion.vb` is import, not export.** Despite the name, the only export logic lives in `modExport.vb`. The class parses `.th` files for import (cSurveyPC/cTherion.vb:828).
- **No PDF writer and no atlas.** "PDF export" means either a PDF printer driver via the standard print dialog, or Therion compiling the exported `.thconfig` (`export map … .pdf`, cSurveyPC/modExport.vb:2897) — the TherionPad ribbon button does the latter in one click (cSurveyPC/frmMain2.vb:9953). Printing is strictly one page (no `HasMorePages` anywhere).
- **`frmExportTherion` mixed setting keys**: it *loads* the thconfig checkbox from `data.export.holos.createthconfig` but *saves* to `data.export.therion.createthconfig` (cSurveyPC/frmExportTherion.vb:5,11) — the saved value is never read back (long-standing bug; symptom: checkbox never remembers).
- **Splay flags are two independent knobs**: `SegmentSplayWithoutName` (anonymize with `.`) and `CalculateSplay` (emit the `splay` flag). frmMain2 always sets `CalculateSplay` for user exports (:5689); the internal calc export sets it too (cCalculate.vb:1663) but never `SegmentSplayWithoutName`.
- **KML/therion exports can pop message boxes** (`GoogleKmlExportTo2` at cSurveyPC/modExport.vb:548) — not fully silent for automation even though they live in `modExport`.
- **Scrap coordinates are ×4-scaled and Y-flipped** relative to cSurvey design coordinates (cSurveyPC/modExport.vb:2260, 2444); station points in scraps use 7-decimal precision, geometry 2-decimal.
- **A scrap is skipped if it would contain ≤2 points** or an empty bounds (cSurveyPC/modExport.vb:2608-2616) — empty branch drawings just don't produce `.th2` files.
- **Point joins are not exported**: the therion `join` generation is intentionally disabled (comment block at cSurveyPC/modExport.vb:2585-2606) because exported point identity may differ from the drawing.
- **`ExecuteTherion` writes an empty line to therion's stdin and can show a "still running" prompt after 120 s** (cSurveyPC/modMain.vb:387-395) — use `ExecuteTherionAsync` (throws `TimeoutException` instead, :298) for unattended runs.
- **`GetTherionGradientOption`/`GetTherionLSizeOption` are dead**: both `Return ""` before their `Select Case` (cSurveyPC/modExport.vb:2304-2322).
- **frmPreview manual-refresh mode**: with `preview.manualrefresh` (or Ctrl/Alt held while opening) the first render paints gray until Refresh is pressed (frmPreview.vb:86, 971) — exports call `btnRefresh.PerformClick()` first (frmPreview.vb:1492) but a screenshot-based automation of this form must account for it.
