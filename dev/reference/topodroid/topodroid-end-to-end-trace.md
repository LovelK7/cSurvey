# TopoDroid import: end-to-end execution trace

## Purpose

This is the execution-level companion to [topodroid-import.md](topodroid-import.md): a numbered, line-cited trace of everything that runs when TopoDroid data enters cSurvey, from the ribbon click through the fix-up pipeline, object construction, event storms, recalculation, and the final on-disk state of `_data.xml`. It exists so an agent can (a) put a breakpoint on any step of the import, and (b) re-implement the import programmatically without the UI (see the appendix).

## Domain concepts

Only concepts this doc adds on top of [topodroid-import.md](topodroid-import.md):

- **Two TopoDroid csx generations.** *Old* TopoDroid wrote a full cSurvey-shaped file: `<plan><layers><layer><items><item>...` with integer segment ids referenced by `S<id>` tokens in `points/@data`. *New* TopoDroid writes the drawing as flat `<item>` children directly under `<plan>`/`<profile>` (no `<layers>`). The code distinguishes them by `modXML.ChildElementExist(oXMlPlan, "layers")` (cSurveyPC/modImport.vb:429, :354). Both paths are still live.
- **Fix-up phase 1 vs phase 2.** Phase 1 (`FixTopodroidCSX`) mutates the raw `XmlDocument` *before* any object is constructed — anything that affects deserialization (ids, attribute shapes) happens here. Phase 2 (`FixTopodroidDesign` + `FixTopodroidSurvey`) runs *after* the full object model exists and the first calculation has completed — it re-reads the raw `<plan>`/`<profile>` XML elements to materialize the new-format flat items, and stamps/binds everything.
- **The second in-memory survey.** Import-merge never parses the foreign file into the open survey. It loads it into a *complete second `cSurvey` instance* (with its own calculation), then copies objects across by round-tripping each one through its own XML serializer (`SaveTo` → `New`/`CreateItem`). The foreign survey is discarded at the end of the `Using` block.
- **`oDuplicatedSegments` id map.** During segment merge a `Dictionary(Of String, String)` maps *imported* segment GUID → *target-survey* segment GUID (identical for non-duplicates, old→existing for duplicates). Every drawing item copied later has its `S<guid>` point tokens, `crosssection` and `segment` attributes rewritten through this map (cSurveyPC/frmMain2.vb:12023, :12253, :12261, :12401).

## Architecture

There are exactly two executable routes for a TopoDroid-exported `.csx`/`.csz` (the therion `.th`/`.th2` routes are traced in [topodroid-import.md](topodroid-import.md) flows 3–4 and not repeated here):

1. **Open** (replace the current survey): `frmMain2.pSurveyLoad` → `cSurvey.Load(Filename)` — TopoDroid detection is automatic via `properties/@creatid` (cSurveyPC/cSurvey.vb:943). Everything happens inside `Load`; the UI only wraps it in event-suppression flags.
2. **Import/merge** (into the open survey): `frmMain2.pSurveyImportcSurvey` → `cSurvey.Load(Filename, LoadOptionsEnum.FixTopoDroid)` on a *second* survey (fix-ups forced regardless of creator), recalculate it, show `frmImportcSurvey`, then copy caves → grades → sessions → highlights → segments → trigpoints → graphics → cross-sections → legends, and finally force-recalculate the target.

Data-flow in one sentence: raw XML fix-up (GUIDs, uppercase) → normal deserialization (segments absorb DistoX attrs, plan/profile ignore the flat items) → full recalculation (TopoDroid files have version `-1`, no `<calculate>` cache) → sketch materialization (`ConvertDesign`/`ConvertItem` create typed layer items from the flat `<item>` list) → stamping + `BindSegments()` on every item → (merge route only) per-object copy into the target with id remapping and warping → save stamps `creat_postprocessed="1"` so the fix-ups never run twice.

### What a TopoDroid csx contains (as the import code reads it)

No TopoDroid-fresh sample exists in this repo (see the buless note below), so this is reconstructed from the exact attributes the code consumes:

- `<csurvey version="-1" ...>` — meta version "generated by other software, no calculate data"; accepted as-is with no format conversion (cSurveyPC/cSurvey.vb:953).
- `<properties creatid="topodroid" creatversion="x.y.z" origin=... ><note>…</note><sessions>…<caveinfos>…` — `creatid`/`creatversion` read at cSurveyPC/cProperties.vb:1033-1034; the survey note is a **child element**, not the attribute cSurvey uses (converted at cSurveyPC/modImport.vb:392-394). Session dates may be `yyyy.mm.dd` or `yyyy-mm-dd` (cSurveyPC/cSession.vb:395-403 — cited in topodroid-import.md).
- `<segments><segment id="<int>" from= to= distance= bearing= inclination= [splay= duplicate= surface=] [g= m= dip= distox=] ...>` — non-GUID ids (regenerated at modImport.vb:397-410), lowercase station names (uppercased :408-409), raw DistoX calibration attrs `g/m/dip/distox` (absorbed at cSurveyPC/cSegment.vb:735-740).
- `<plan>` / `<profile>` containing either `<layers>` (old format) or direct `<item type="line|area|point" name="wall|water|section|…" cave= branch= [closed reversed outline orientation scale text stationfrom stationto sectionname sectiontext options]><points data="…"/>[<crosssection>…</crosssection>][<crosssectionfile><attachment data= dataformat= type=/></crosssectionfile>]</item>` (new format) — every attribute here is read in cSurveyPC/cImportTopoDroidHelper.vb:69-92, :113-116, :174, :344, :352-353, :363-364, :368-372.
- Optionally `<crosssections>` with the same non-GUID id problem (modImport.vb:413-425).

### buless.csz reality check

`dev/example/buless.csz` was assumed TopoDroid-derived; extraction shows it is actually a **PocketTopo** import, later fully post-processed by cSurvey: `_data.xml` is `<csurvey version="1.11">`, has **no** `creatid`/`creat_postprocessed` attributes, and every segment `<datarow>` reads `2015-06-13T16:36:00…|pockettopo` (verified by extracting with 7za and grepping). It is still the best in-repo specimen of the **final state** any importer converges to — see the "Final state of `_data.xml`" section.

## Key flows

### Flow A — Open a TopoDroid .csx/.csz (File → Open, replaces current survey)

1. cSurveyPC/frmMain2.vb:16596-16598 — ribbon `btnLoad_ItemClick` → `pSurveyLoad()`; or drag & drop of a csx/csz onto an **empty** survey routes here too (frmMain2.vb:8501-8503).
2. cSurveyPC/frmMain2.vb:776 — `cSurvey.cSurvey.Check(Filename)` pre-gate (therion path configured etc.); on success a fresh `oSurvey = New cSurveyPC.cSurvey.cSurvey` (:780).
3. cSurveyPC/frmMain2.vb:804-806 — UI event suppression armed: `bDisabledCaveBranchChangeEvent = True`, `bDisableSegmentsChangeEvent.Push()`, `bDisableTrigpointsChangeEvent.Push()` (so the thousands of per-segment events raised during load do not each trigger recalculation/repaint).
4. cSurveyPC/frmMain2.vb:808 — `oResult = oSurvey.Load(Filename)` — **everything TopoDroid happens inside this call (steps 5-16)**.
5. cSurveyPC/cSurvey.vb:940-941 — `Using oFile As cFile = New cFile(Filename)`: `.csx` parsed as bare XML, anything else opened as a zip whose `_data.xml` becomes `oFile.Document` (`New(Filename)` ctor cSurveyPC/cFile.vb:66-81; zip extraction cSurveyPC/cFile.vb:386-403).
6. cSurveyPC/cSurvey.vb:943-945 — detection: `pGetFileCreatID(oXml) = "topodroid"` (reads `properties/@creatid`, lowercased, :1755-1761) **and not** `pGetFileCreatPostProcessed(oXml)` (reads `creat_postprocessed`, :1747-1753; note the `Catch → Return True` — a malformed properties node *disables* fix-ups), **or** `LoadOptionsEnum.FixTopoDroid` was passed, **or** the hidden Ctrl+Shift opening flag `modOpeningFlags.OFRegenerateSegmentsID` → `modImport.FixTopodroidCSX(oXml)`.
7. cSurveyPC/modImport.vb:384-441 — **phase-1 DOM fix-up**:
   - :388-390 uppercase `properties/@origin`;
   - :392-394 copy `<properties><note>` child into the `note` attribute;
   - :397-410 for every `<segment>`: if `id` is non-empty and not a parseable `Guid`, record old→new in `oSegmentIDs` and overwrite with `Guid.NewGuid`; always uppercase `from`/`to`;
   - :413-425 same GUID regeneration for `<crosssections>` children;
   - :427-440 **old format only** (`<plan>/<layers>` exists): walk every layer's `<items>/<item>` and `ReplaceIDItem` (:451-480) which rewrites `crosssection`/`segment` attributes and does a string replace of `"S<oldid> "` → `"S<newid> "` inside `points/@data` (:443-449; the data string is padded with a trailing space first so the last token matches). **New-format flat items are NOT id-rewritten here** — they don't carry `S` tokens from TopoDroid (binding is created later in step 16).
8. cSurveyPC/cSurvey.vb:950-953 — version switch: TopoDroid's `-1` matches `Case Version, "-1"` → `bOk = True`, no format upgrade loop.
9. cSurveyPC/cSurvey.vb:1264-1272 — `oProperties = New cProperties(Me, oXmlRoot.Item("properties"))`; inside, `creatid`/`creatversion` are captured (cSurveyPC/cProperties.vb:1033-1034) — from here on `Survey.Properties.CreatorID = "topodroid"` drives the remaining special-casing.
10. cSurveyPC/cSurvey.vb:1296 — `oSegments = New cSegments(Me, oFile, oXmlRoot.Item("segments"))` (NOT try/catch-guarded — a broken `<segments>` is fatal). In the ctor:
    - cSurveyPC/cSegments.vb:191-208 — because `CreatorID = "topodroid"`, four segment data-table fields are auto-created: `distox_g`, `distox_m`, `distox_dip` (Single) and `distox` (Text), all Category `"DistoX"`;
    - :214-223 — per `<segment>`: `New cSegment(oSurvey, File, oXmlSegment)` then four handlers attached (`OnChange`, `OnSplayChange`, `OnReassigned`, `OnGetSplayName`).
11. cSurveyPC/cSegment.vb:648-743 — single-shot deserialization: id (fresh GUID if empty :651-652), from/to/distance/inclination/bearing, `l/r/u/d`, flags with coupling enforced — `Cut → Splay` (:684) and `Splay|Duplicate|Surface|Calibration → Exclude` (:685) — cave/branch/session strings (:690-694), splay-border tuning attrs (:699-707), cached plot `<data>` child if present (:714-718), `<datarow>` DataProperties (:726-730), and **TopoDroid-only** absorption of `g/m/dip/distox` attributes into the DistoX DataProperties (:735-740).
12. cSurveyPC/cSurvey.vb:1299-1303 — trigpoints; :1386-1399 — `oPlan = New cDesignPlan(Me, oFile, oXmlRoot.Item("plan"))` and profile. These ctors consume only the `<layers>` child; **new-format flat `<item>` children are silently ignored at this stage** (they are only materialized in step 16).
13. cSurveyPC/cSurvey.vb:1532-1539 — no `<calculate>` element in a TopoDroid file → `oCalc = New cCalculate(Me)` with `bDoCalculate = True` (`LoadedFromFile` stays False, cSurveyPC/Calculate/cCalculate.vb:104-108, set True only by the XML ctor at :122).
14. cSurveyPC/cSurvey.vb:1541-1543 — if `properties/@origin` was empty, `AutoSetOrigin()`.
15. cSurveyPC/cSurvey.vb:1547-1550 — `Invalidate()` (sets `iInvalidated = FullCalculate`, :1939-1941) then `oCalc.Calculate(False)` — **the first full calculation, including the Therion round-trip, runs during Load** (see Flow C); `PerformWarping:=False`.
16. cSurveyPC/cSurvey.vb:1566-1570 — **phase-2 fix-up**, same trigger condition as step 6:
    - `modImport.FixTopodroidDesign(Me, oPlan, oXmlRoot.Item("plan"))` and same for profile → `cImportTopoDroidHelper.ConvertDesign(Survey, Design.Layers, Items)` (cSurveyPC/modImport.vb:330-332) which loops `Items.SelectNodes("item")` — i.e. only **direct** `<item>` children of `<plan>`/`<profile>` (cSurveyPC/cImportTopoDroidHelper.vb:54-58). For a native/old-format file this list is empty and the pass is a no-op. Whatever TopoDroid placed under `<plan>` lands in `Survey.Plan`, `<profile>` in `Survey.Profile` — the converter is design-agnostic.
    - Each `<item>` goes through `ConvertItem(Survey, Layers, XMLItem, cItem.BindDesignTypeEnum.MainDesign)` (:112-401): the `type`/`name` double `Select Case` picks a typed layer factory (full mapping table in [topodroid-import.md](topodroid-import.md)); every branch then runs the same 5-step recipe — factory-create (item already added to its layer), `SetBindDesignType(...)`, `Points.Parse(XMLItem.Item("points"))`, optional `MoveBy(Location)`, then for line/area branches `pConvertItem` (:68-77) which **reverses point order when `reversed=0`** and closes sequences when `closed=1`; point/sign branches call `pConvertSign` **instead** (:79-93, orientation + TopoDroid scale −2..2 → `SizeEnum` via :95-110), never both.
    - `point section` items (:351-379) resolve their shot via `Survey.Segments.Find(stationfrom, stationto, True)` (cSurveyPC/cSegments.vb:602), create a `cItemCrossSection` via `Layers.SignsLayer.CreateCrossSection`, recursively convert the nested `<crosssection>` item list with `ConvertCrossSection` (:60-66, null-guarded `If Items IsNot Nothing` — the 0b90671 crash fix) into the item's own `DesignCrossSection`, and decode an optional base64 `<crosssectionfile>` into `Survey.Attachments.Add` + a `cItemAttachment` (:368-377).
    - `modImport.FixTopodroidSurvey(Me, oXmlRoot)` (cSurveyPC/modImport.vb:334-381) — idempotency guard: only runs when the Segments data-table lacks `import_source`/`import_date` (:335). Adds those two fields to the Segments and DesignItems tables, stamps every segment (:342-345) and every design item (:349-352) with `import_source = If(CreatorID = "", "topodroid", CreatorID)` and `import_date = CreationDate|Now` (:336-337); if the old `<plan><layers>` format is present, executes the `C` (close-sequences) points meta (:354-366); in all cases clears metas and calls **`oItem.BindSegments()` on every design item** (:368, :377 — "topodroid don't do it itself"), which parallel-binds each unlocked point to the nearest same-cave/branch centerline segment (cSurveyPC/cItem.vb:796-841 via `cDesign.GetNearestSegment`).
17. cSurveyPC/cSurvey.vb:1572 — `Return New cActionResult(True, "", "")`; back in `pSurveyLoad` the suppression flags pop (frmMain2.vb:810-813), tools/grids/dock panels are rebuilt (:823-854), plan view shown (:851).
18. First save: cSurveyPC/cProperties.vb:1182-1185 — because `sCreatorID <> ""`, SaveTo writes `creatid`, `creatversion` **and `creat_postprocessed="1"`**, so steps 6-7 and 16 never run again on this file; the file also now carries `version="1.14"` and the full `<calculate>` cache, so subsequent loads skip recalculation.

3. cSurveyPC/frmMain2.vb:11862-11865 — `If Not oImportSurvey.Calculate.LoadedFromFile Then oImportSurvey.Invalidate() : oImportSurvey.Calculate.Calculate(True)` — guarantees the foreign survey has station coordinates (needed for warping/translation math later).    - :11880-11882 source app detection via `oImportSurvey.Properties.CreatorID = "TopoDroid"` (+ version);
   - :11892-11899 **hard gate**: if the two surveys share zero trigpoint names it is an error → data + graphics import disabled (:11980-11981);
   - :11901-11907 data-table mergeability (`CanMergeWith`) — another hard gate;

   - **grades** :12080-12086; **sessions** matched by `(Date, Description)` then `CopyFrom` (:12089-12099 — overwrites same-key sessions, see comment :12097); **non-system highlights** :12101-12106;
   - **segment data-tables** merged :12111-12112;
   - **segments loop** :12116-12264 — each `oImportSegment` is round-tripped: `SaveTo(oFile, oXML, oXMLParent, Silent Or ForClipboard)` (:12123) → `New cSegment(oSurvey, oFile, oXMLParent.ChildNodes(0))` (:12125) so the copy is parented to the *target* survey. Duplicate detection per `cbocSurveyImportDuplicatesMode.SelectedIndex`: 0 = same GUID already in `oSurvey.Segments` (:12130), 1 = `oSurvey.Segments.FindDuplicate(oImportSegment)` by data (:12134). Duplicates: skipped, or overwritten wholesale (:12204-12227), or field-by-field per the `frmImportcSurveyShotsDetails` matrix (:12153-12202; the reflection pass :12190-12199 copies any `cSegment` property tagged `cReplicateDataAttribute`; the `DataProperties` key has the known trailing-space settings bug). Non-duplicates: `oSurvey.Segments.Append(oNewSegment)` (:12256; raises `OnSegmentBeforeAppend`/`OnSegmentAppend`, cSegments.vb:272-282) and splays get a fresh generated To-name `basename(n)` (:12257-12260, generator cSegments.vb:314-333). Either way the id map is extended (:12253/:12261).
   - **trigpoints** :12267-12297 — `oSurvey.TrigPoints.Rebind()` first (:12269) so stations exist for the new shots; then for every non-system imported trigpoint, entrance/exploration/note/label/type/coordinate/aliases/connections/data are copied onto the same-name (uppercased :12274) station — new stations always, pre-existing ones only if `chkcSurveyImportDuplicatesStations` (:12276).

   - :12314 design-item data-tables merged;
   - :12318-12333 translation fallback: when nothing is segment-bound (or mode 2 "always translate"), the target is recalculated (:12320) and plan/profile translation vectors are computed from the **two origins' positions in the target's own calculation** (`oSurvey.Calculate.TrigPoints(oImportSurvey.Properties.Origin)` — works because the surveys share stations);

### Flow C — Events and recalculation during import

1. **Append events**: `cSegments.Append(Segment)` raises `OnSegmentBeforeAppend` then `OnSegmentAppend` (cSurveyPC/cSegments.vb:272-282); `cSurvey` forwards segment changes as `OnSegmentsChange` and ORs each segment's invalidation flags into `iInvalidated` (cSurveyPC/cSurvey.vb:1919-1924).
2. **UI reaction**: `frmMain2.oSurvey_OnSegmentsChange` (frmMain2.vb:5491-5518) marshals via `InvokeRequired/Invoke`, and — *unless `bDisableSegmentsChangeEvent` is pushed* — reacts per action: `BeforeAdd` assigns the currently-selected cave/branch to the new segment (:5500), `Add/Change/Splay/Remove/Clear` all call `pSurveyCalculate(False)` (recalc only if `CalculateMode = Automatic`). This is why every bulk import wraps mutations in `bDisableSegmentsChangeEvent.Push()/.Pop()` (a counter stack) — without it each appended shot would trigger a full Therion recalculation.
3. **The calculation itself** (`cCalculate.Calculate`, cSurveyPC/Calculate/cCalculate.vb:576): clears cached data (:580); for full/partial invalidation `oSurvey.TrigPoints.Rebind()` **materializes stations from segment names** (:590) — this is where TopoDroid stations become `cTrigPoint`s; validates origin exists and is not orphan (:592-597), GPS ref coordinate (:599-614), **every non-equate/non-virtual shot has a session when `CalculateVersion > 2`** (:621-627, throws `cCalculateMissingSessionException`), and network connectivity (:640-649, `cCalculateOrphanShotsException`). Then `FullCalculate` → Therion round-trip `pCalculateSegments` (:651) + `pCalculateGeographics` (:653). Warping is skipped when `PerformWarping:=False` (Load path) or invalidation ≤ PartialCalculate (:658-663).
4. **Post-calculate**: `cSurvey.oCalc_OnCalculateComplete` (cSurveyPC/cSurvey.vb:1963-1968) resets `iInvalidated`, invalidates both plot caches (`oPlan.Plot.Redraw()`/`oProfile.Plot.Redraw()`), and raises `OnCalculate` for the UI.
5. **Result handling**: `Calculate` never throws to the caller — errors come back typed in `cActionResult.Exception`, mapped to grid-row annotations and popups in `pSurveyCalculate` (frmMain2.vb:5551-5572).

### Final state of `_data.xml` after import (verified against buless.csz)

After import + save, the file is indistinguishable from a native survey except for the audit trail. Concretely (all verified in the extracted `dev/example/buless.csz`, plus the serializers cited):

- `<csurvey version="1.11+">` with a full `<calculate>` element — next load skips recalculation (cSurveyPC/cSurvey.vb:1533-1535).
- `<properties>/<datatables>` gains `<segments><datafield name="import_date" type="5"/><datafield name="import_source" type="0"/></segments>` and the identical pair under `<designitems>` (writer: modImport.vb:339-348 for TopoDroid; sibling importers add the same fields). TopoDroid files additionally get the four `DistoX` fields (cSegments.vb:191-208).
- Every `<segment>` has a GUID `id`, uppercase `from`/`to`, coupled flags (e.g. buless: `exclude="1" surface="1"`, `exclude="1" splay="1"`), cave/branch/session strings, splay-border tuning attributes, and a `<datarow>` whose pipe-separated positional payload carries the stamps — buless: `2015-06-13T16:36:00.5114087+02:00|pockettopo` (a TopoDroid import reads `…|topodroid`).
- Splays materialized as real segments with generated To-stations `0.1(1)`-style (267 of 316 segments in buless are `splay="1"`).
- Drawing items live under `<plan>/<layers>/<layer>/<items>/<item>` with `points/@data` carrying centerline bindings — buless sample: `data="34.74 22.69 BS40eee7c4-…-68933eeba3ef 35.28 22.03 S 36.63 21.16 S …"` (`B` = begin sequence, `S<guid>` = bound segment, bare `S` = same segment as previous point; parser cSurveyPC/cPoints.vb:564-601).
- `<crosssections>` children all carry GUID ids.
- For the TopoDroid open-route, `<properties>` additionally keeps `creatid="topodroid" creatversion="…"` and gains `creat_postprocessed="1"` (cSurveyPC/cProperties.vb:1182-1185). buless has none of these because the PocketTopo importer builds the survey in-memory rather than loading a foreign-creator file.

## Appendix — minimal programmatic import (no UI)

**Case 1 — TopoDroid export becomes a new survey** (the common automation case). The whole conversion is inside `cSurvey.Load`; this exact sequence is what `pSurveyImportcSurvey` runs at frmMain2.vb:11860-11865:

```vb
Dim oSurvey As New cSurveyPC.cSurvey.cSurvey()
Dim oResult = oSurvey.Load("phone.csx", cSurveyPC.cSurvey.cSurvey.LoadOptionsEnum.FixTopoDroid) ' flag optional if creatid="topodroid" is present
' Load already ran a full Calculate(False); force one more with warping if you mutated anything:
If Not oSurvey.Calculate.LoadedFromFile Then
    oSurvey.Invalidate()
    Dim oCalcResult = oSurvey.Calculate.Calculate(True)   ' Friend — in-assembly only
End If
Call oSurvey.SaveTo("cave.csz")                            ' stamps creat_postprocessed, embeds <calculate>
```

Public/Friend boundary on this path: `cSurvey.New/Load/SaveTo/Invalidate` are `Public` (cSurvey.vb:936, :1939); `cCalculate.Calculate` is **`Friend`** (cCalculate.vb:576) and `cItem.BindSegments` is **`Friend`** (cItem.vb:796) — a driver must live in the cSurveyPC assembly, use `InternalsVisibleTo`, or rely on `Load` having already done both (it has: step A15 calculates, step A16 binds). `cImportTopoDroidHelper.ConvertDesign/ConvertCrossSection/ConvertItem` are `Public Shared` (cImportTopoDroidHelper.vb:54, :60, :112) and callable directly if you need to convert sketch XML outside `Load`.

Preconditions for the embedded calculation to succeed (Flow C step 3): `therion.path` setting resolves to therion.exe; origin station present (auto-set at cSurvey.vb:1541-1543); every shot has a session; network connected. Also note the general headless blockers documented in [automation-surface.md](../automation-surface.md) (settings/localization initialization).

**Case 2 — merge into an existing survey.** There is **no UI-free equivalent**: the ~740-line merge loop (Flow B steps 5-6) lives in `frmMain2.pSurveyImportcSurvey` and reads its options directly off `frmImportcSurvey` controls (e.g. `frmIS.cbocSurveyImportDuplicatesMode.SelectedIndex` at frmMain2.vb:12126). To automate a merge you must re-implement the loop from the building blocks, all of which are UI-free:

1. Load the foreign file as in Case 1.
2. Copy caves/sessions/grades via `MergeWith`/`CopyFrom` (frmMain2.vb:12040-12099 is the reference implementation).
3. Per segment: `SaveTo(oFile, oXML, oXMLParent, Silent Or ForClipboard)` → `New cSegment(target, oFile, xml)` (`Friend` ctor, cSegment.vb:648) → duplicate check `target.Segments.Contains(id)` or `FindDuplicate(seg)` (cSegments.vb:571) → `target.Segments.Append(seg)` (`Public`, cSegments.vb:272) → splay rename via `seg.GetSplayName()` (frmMain2.vb:12257-12260) → maintain the old→new id dictionary.
4. `target.TrigPoints.Rebind()`, copy station extras (frmMain2.vb:12269-12296).
5. Per item: `SaveTo(..., ForImport)` → `modImport.ReplaceIDItem(xml, idMap)` (`Public`, modImport.vb:451) → `target.Plan/Profile.Layers(layerType).CreateItem(oFile, xml)` → `RebindSegments(idMap)` (`Friend`, cItem.vb:769) → warp with `WarpItemsEx` + `cPlanWarpingFactor(newSeg, oldSeg)` or translate by origin delta (frmMain2.vb:12341-12353, :12318-12333).
6. `target.Invalidate()` + `target.Calculate.Calculate(True)`.

Do **not** subscribe UI handlers to `OnSegmentsChange` during step 3, or replicate the `bDisableSegmentsChangeEvent.Push()/Pop()` guard; headless code that simply has no subscribers is safe.

## How to modify safely

- **Keep the two-phase split.** Anything affecting deserialization (ids, attribute names/shapes) must go in `FixTopodroidCSX` (pre-parse); anything needing `Survey.Segments`/`Layers` must go in `FixTopodroidDesign`/`FixTopodroidSurvey` (post-calculate). Both share one trigger expression duplicated at cSurvey.vb:943 and :1566 — change them together.
- **Preserve the idempotency guards**: `creat_postprocessed` (cSurvey.vb:943/:1566, stamped cProperties.vb:1185) and the `import_source`-field check (modImport.vb:335). A fix-up outside these guards will re-run on every load of an already-converted file.
- **The id map must reach every reference.** Segment ids appear in three places: `points/@data` `S` tokens, `item/@crosssection`, `crosssection-item/@segment`. `ReplaceIDItem` (modImport.vb:451-480) and `RebindSegments` (cItem.vb:769) are the only two rewriters; extending the schema with a new segment reference means extending both.
- **Order matters in the merge**: data-tables before segments (datarows are positional), segments before `TrigPoints.Rebind`, rebind before trigpoint copy, plain items before linked items (cross-section index must exist), items before legends (legend entries point at copied items).
- **`FixTopodroidSurvey` force-binds everything** — if you create items during import, give them cave/branch *before* it runs, or `BindSegments` will unbind them (empty cave + MainDesign → bind to Nothing, cItem.vb:797-801).
- **Don't call `ConvertDesign` with a missing element**: `FixTopodroidDesign` passes `oXmlRoot.Item("plan")` unguarded (cSurvey.vb:1567); a csx with no `<plan>` element at all would NRE in `Items.SelectNodes` (cImportTopoDroidHelper.vb:55) (inferred — TopoDroid always writes both elements in practice).

## Gotchas

- `pGetFileCreatPostProcessed` returns **True on exception** (cSurvey.vb:1750-1751): a file whose `<properties>` is malformed will *skip* TopoDroid fix-ups rather than fail — segments then load with integer ids and collide/throw in the keyed collection.
- The ribbon passes `True` as `FilterIndex` (frmMain2.vb:16689) — VB coerces it to −1, meaning "last used filter". The hard-coded index routes (drag & drop :8501-8505, menu shortcuts) pass real indices; reordering the dialog filter string at :579 breaks them silently.
- Merge-loading **any** file through `pSurveyImportcSurvey` forces `FixTopoDroid` (frmMain2.vb:11861): a pristine native cSurvey source without import stamps gets `import_source="topodroid"` on every segment/item (modImport.vb:336) and all its items force-rebound. Harmless for geometry, misleading for provenance queries.
- `pConvertItem` reverses point order when `reversed` is **0** (cImportTopoDroidHelper.vb:69-72) — TopoDroid's native order is the opposite of cSurvey's; do not "fix" the apparent inversion.
- The dialog's unbound-profile-points check inspects `Plan` twice (frmMain2.vb:11939-11940) — the profile warning line is wrong.
- Old-format `S<id>` rewriting is string-`Replace` based on `"S<id> "` with a trailing space (modImport.vb:443-449); ids that are prefixes of other ids are safe only because of that trailing space — keep it.
- The first `Calculate` runs **inside `Load`** (cSurvey.vb:1549) — a TopoDroid import with a missing session or disconnected splay fails there, not at explicit calculate time; `Load` still returns success (calculation errors surface via `cActionResult` of the *next* `Calculate` call or grid annotations).
- Duplicate-mode 0 matches by segment **GUID** — meaningless for two independent TopoDroid exports of the same cave, since `FixTopodroidCSX` regenerates ids randomly on each load; use mode 1 (data match) for repeat-trip merges.
- buless.csz is a **PocketTopo**-derived file, not TopoDroid — use it as a final-state reference only.
