# cSurvey knowledge base (AI-oriented)

This documentation set was generated by a multi-agent deep-dive of the codebase (July 2026) and adversarially fact-checked against the source — claims carry `path:line` citations relative to the repo root. It exists so that any AI agent (or human) can (a) diagnose user-reported problems and point to the responsible code, and (b) build automation on top of cSurvey — the target scenario being **TopoDroid import → automated final sketch → exported map**, eventually via an MCP server.

Start with [`CLAUDE.md`](../../CLAUDE.md) at the repo root for the one-page orientation, then drill into the docs below.

## Key facts that survived every check (safe to rely on)

- `.csz` = ZIP with `_data.xml` + binary assets; `.csx` = bare XML; all object cross-references are plain strings/GUIDs — out-of-process manipulation is viable. Stage-0 read-only tooling needs no build at all.
- Network solving is delegated to **external `therion.exe`** (`therion.path` user setting); the "Internal" calculation type is dead code (setter hard-codes Therion).
- TopoDroid interchange = TopoDroid's **exported .csx** (best; auto-fixed and sketch-converted on load via `LoadOptionsEnum.FixTopoDroid`), or therion .th/.th2. The TopoDroid .zip project archive is not readable.
- The proven headless import sequence (used by the UI itself, frmMain2.vb:11860-11865): `New cSurvey` → `Load(path, FixTopoDroid)` → `Invalidate()` → `Calculate.Calculate(True)` → `SaveTo`. Load/SaveTo/Invalidate are Public; a purely Public driver can already do csx→csz conversion because Load runs the calculation and binding internally.
- Plan cave walls can already be auto-generated from splays: `modSegmentsTools.CreatePlanBorderFromSplay` (cSurveyPC/modSegmentsTools.vb:424) — but it is debug-gated in the UI and **never binds its output** (must call `BindSegments()` after, or the border won't warp). The profile counterpart is an empty stub — the main missing piece for full auto-sketch.
- LRUD-based alternatives are useless on phone-surveyed data: real imports (see `buless.csz`, which is PocketTopo-derived, 267/316 splays) carry **no LRUD values at all**; nothing in the codebase derives LRUD from splays.
- The domain core is headless-capable but sits behind `Friend` accessibility and WinForms-initialized settings; the recommended seam is a net48 worker host + a ~100-line Public facade (`cAutomation`) inside cSurveyPC, fronted by a modern-.NET MCP stdio process (see mcp-blueprint.md). No `InternalsVisibleTo` exists today.
- Compile blocker for anything beyond Stage 0: DevExpress v24.2 GAC references + licenses.licx.

## Known gaps (from the completeness audit — undocumented, expand on demand)

A final audit tested the docs against realistic diagnosis/automation scenarios; all passed. These subsystems remain undocumented — none block the TopoDroid automation goal, but a user report touching them has no doc trail yet. Pointers for whoever documents them next:

- **Autosave / file history / crash recovery** (medium) — full history engine (`HistoryModeEnum` Folder/Web/Both, autosave thread, emergency save on unhandled exception): frmMain2.vb:111-131, :1094-1240, :1146-1172, :9657+; ApplicationEvents.vb:35-43; frmExceptionManager.vb.
- **Linked surveys & master/slave** (medium) — external .csz references by lowercased path (classic "linked survey vanished after moving folders"): cLinkedSurveys.vb, cMasterSurvey.vb, frmMasterSlaveManager.vb.
- **Resurvey subsystem** (medium) — parallel `.crsx`/`.crsz` document type + editor (~7k lines) for digitizing legacy paper maps: cResurvey.vb, frmResurveyMain.vb, frmImportResurvey.vb.
- **Settings-key inventory** (low) — no consolidated table of the ~750 `GetSetting` sites (HKCU\Software\Cepelabs\cSurvey) and frmSettings map.
- **Undo internals** (low) — snapshot lifecycle, whether programmatic mutations snapshot at all: cUndo.vb, cEditTools.vb:1901-1917.
- **Cave register + web services** (low) — frmCaveRegister script bindings, web history upload, cLocalSecurity TripleDES.
- **Logging** (low) — there is **no log file**: the console dock is the only sink; therion's own `%TEMP%\_therion*_log.log` is the only persistent diagnostic artifact. (`cSurveyDiagnostics` is an empty test shell, not a crash reporter.)
