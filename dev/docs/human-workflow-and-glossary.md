# Human workflow & domain glossary

## Purpose

This doc bridges the vocabulary a caver (and the cSurvey manuals) use to the vocabulary the codebase uses. It describes the canonical end-to-end workflow — field survey with DistoX+TopoDroid, import, data review, drawing plan/profile, annotation, print/export — stage by stage with UI locations, decodes the six-stage demo tutorial (`dev/example/Demo Survey/survey_1.csz` … `survey_6.csz`), and defines every domain term an AI agent needs, each tied to its code-side class or XML element.

Sources: the English manual `dev/literature/csurvey.it.en.pdf` (machine-translated from Italian, ~2011 feature level, 70 pp), the 2020 rapid tutorial `dev/literature/cSurvey_RAD_Paride.pdf` (Croatian, 42 pp, covers the modern UI incl. TopoDroid/PocketTopo file interchange), the demo survey files, and the code itself.

## Domain concepts — THE GLOSSARY

### Survey-data terms

- **Station** (trigpoint, IT *caposaldo*): a fixed survey point in the cave; shots are measured between stations. Code: `cSurveyPC/cTrigPoint.vb:5` (`Public Class cTrigPoint`), collection `cTrigPoints` (`cSurveyPC/cTrigPoints.vb:5`), XML `<trigpoint name="A0" entrance="2">` under `<trigpoints>`. Stations are *derived* from shots ("Regenerate trigpoints" in the UI; stale ones are removed with "Remove orphans" — manual p.4). Station names must not contain spaces and are case-insensitive (uppercased on TopoDroid import, `cSurveyPC/modImport.vb:408-409`).
- **Shot** (segment, leg; IT *battuta*): one measurement between two stations: `from`, `to`, `distance` (m), `bearing` (azimuth, decimal degrees), `inclination` (decimal degrees), plus optional LRUD. Code: `cSurveyPC/cSegment.vb:9` (`Public Class cSegment`), collection `cSegments` (`cSurveyPC/cSegments.vb:6`), XML `<segment from="A0" to="A1" distance="5.60" bearing="288.00" inclination="-30.00" cave="Grotta" branch="Ramo 1\Ingresso" session="20111119_sessione_a">`. Only meters and decimal degrees are supported (manual p.3).
- **LRUD**: Left/Right/Up/Down distances from a station to the walls/ceiling/floor, recorded per shot; drawn as the colored "Areas" around the centerline. XML attributes `l`, `r`, `u`, `d` on `<segment>` (see survey_1.csz). Missing LRUD at an end station can be supplied via a **self-defined shot** (from==to, e.g. `1→1`), drawn perpendicular to the outgoing shot (manual p.21).
- **Splay**: a shot from a station to a wall point (no named target), used to capture passage shape; with a DistoX the splays vastly outnumber real shots (manual p.23, "The splay"). Code: `cSegment.Splay` property (`cSurveyPC/cSegment.vb:617`); auto-splay mode `cSurvey.SplayModeEnum {None, Automatic}` (`cSurveyPC/cSurvey.vb:99-102`). With automatic mode on, a shot entered as `1 → <empty>` gets a synthetic target name `1(1)`, `1(2)` … generated by `cSegments.GetSplayName` (`cSurveyPC/cSegments.vb:308`). Real TopoDroid data confirms the convention: buless.csz has 316 segments of which 267 have `splay="1"` and targets like `0.1(1)`. Splays are excluded from length statistics (`exclude="1"`) and by default not used for binding graphic objects; they are projected radially to support cross-section drawing (manual p.23-24).
- **Duplicate / Surface / Exclude flags**: per-shot booleans marking a shot as a duplicate of another, as a surface (above-ground) leg, or excluded from statistics. Code: `cSegment.Duplicate` (`cSurveyPC/cSegment.vb:538`), `.Surface` (`:556`); XML `exclude="1"`.
- **Origin**: the single station used as Cartesian (0,0,0) from which the whole centerline is computed; **mandatory** — no calculation happens without it (manual p.3, RAD p.13). XML `<properties origin="A0">`. Usually the entrance.
- **Cave / Branch**: hierarchical grouping of shots and drawing objects. A survey holds named *caves*, each with a tree of *branches* (e.g. `Ramo 1\Ingresso`); each shot and each drawing item carries `cave`/`branch` strings. Code: `cCaveInfo` (`cSurveyPC/cCaveInfo.vb:6`), `cCaveInfoBranch` (`cSurveyPC/cCaveInfoBranch.vb:5`); XML `<caveinfos><caveinfo name="Grotta"><branches><branch name="Ramo 1">…`. Branch membership drives drawing filters, overlapping-passage handling, offsets in print, and object→centerline binding (manual p.18-19, p.48).
- **Session**: one dated survey trip; carries date, description, color, units, north/declination handling and instrument grade. Every shot references a session. Code: `cSession` (`cSurveyPC/cSession.vb:76`); XML `<session date="2011-11-19T…" description="Sessione A" declinationenabled="0" declination="0.00">`. The RAD tutorial calls sessions "NEOPHODNI" (required) for statistics (RAD p.14).
- **Declination**: magnetic-north correction applied per session (computable from date+location). Code: `cSession.DeclinationEnabled`/`Declination` (`cSurveyPC/cSession.vb:561`, `:584`).
- **Grade / precision degree**: a named accuracy class (max standard deviations of the 3 measurements) attached to a session so loop-closure error is distributed weighted by instrument quality (manual p.22 "Precision Degrees"). Code: `cGrade` (`cSurveyPC/cGrade.vb:4`), `cGrades` (`cSurveyPC/cGrades.vb:13`), `cSession.Grade` (`cSurveyPC/cSession.vb:552`). (Not literally BCRA grades — free-form user-defined classes; "BCRA" appears nowhere in the code.)
- **Loop / ring closure**: when two paths connect the same pair of stations, the misclosure error is computed and distributed. UI: Survey menu → Loops (RAD p.41 "Loops: prikazuje… petljama"). Code: `cCalculate.Plot.cRing` / `cRings` (`cSurveyPC/Calculate/cCalculate.Plot.cRing.vb`, `cCalculate.Plot.cRings.vb`). The manual is blunt: a survey whose rings don't close "will NEVER" be calculable (manual p.9, limitation 3).
- **Entrance**: a station flagged as cave entrance/external point; the anchor for GPS coordinates and georeferencing. Code: `cTrigPoint.EntranceTypeEnum {None, OtherCaveEntrance, MainCaveEntrace, MainComplexEntrance, OutSide}` (`cSurveyPC/cTrigPoint.vb:106-112`); station type `TrigPointTypeEnum {Undefined, Fixed, Painted, Temporary}` (`:99-104`) mirrors Therion station types.
- **Station link / Ignore**: per-station list of connections controlling how the *profile* is unrolled: marking a link "ignore" stops the profile from following that connection, letting the surveyor choose how loops/branches are laid out in the extended elevation (manual p.4, p.27). Code: `cConnection.Ignore` (`cSurveyPC/cConnection.vb:27`).

### Views, drawing & rendering terms

- **Design**: one of the two drawable views of the survey — **plan** (top-down projection) and **profile**. Code: `cDesignPlan` (`cSurveyPC/cDesignPlan.vb:11`), `cDesignProfile` (`cSurveyPC/cDesignProfile.vb:8`), held by `cSurvey.Plan`/`.Profile` (`cSurveyPC/cSurvey.vb:1633,1639`); XML top-level `<plan>` and `<profile>` elements, each containing layers of `<item>`s.
- **Profile / longitudinal section / extended elevation**: cSurvey's profile is NOT an orthogonal projection: each shot is projected onto its own vertical plane and the sequence unrolled left-to-right from the origin ("extended section (or developed)", manual p.26). Direction per shot can be inverted (`Dx/sx` column) and station links "ignored" to control the unrolling. The demo's final output is literally named `Cave - Profile (Extended elevation).pdf`.
- **Plot vs design**: the *plot* is the computed centerline geometry (station coordinates, LRUD areas, rings) produced by calculation — classes under `cSurveyPC/Calculate/` (`cCalculate.Plot.cSubData.vb:156,162` exposes `Plan`/`Profile` sub-data) — while the *design* is the human-drawn vector map on top of it. See [calculation-engine.md](calculation-engine.md) and [rendering-and-plot.md](rendering-and-plot.md).
- **Layer / level**: designs are rigidly structured into 7 fixed layers, bottom to top: Base (sketches/images), Soil, Water & floor morphologies, Rocks & concretions, Ceiling morphologies, Borders, Signs. Code: `LayerTypeEnum {Base=0, Soil=1, WaterAndFloorMorphologies=2, RocksAndConcretion=3, CeilingMorphologies=4, Borders=5, Signs=6}` (`cSurveyPC/cLayers.vb:34-42`). Objects cannot move between layers; everything up to the Borders layer is auto-clipped by the cave border (manual p.6, p.38).
- **Item / graphic object**: anything drawn in a design. Types: `cItemTypeEnum {FreeHandLine=1, FreeHandArea=3, InvertedFreeHandArea=4, Clipart=5, Sign=6, Image=7, Text=8, CrossSection=9, Quota=10, Sketch=11, Attachment=12, Legend=13, Scale=14, Compass=15, InformationBoxText=16, CrossSectionMarker=29, …}` and categories `cItemCategoryEnum {CaveBorder=1, Border=2, LevelLine=3, Rock=0x20, Concretion=0x21, Soil=0x30, WaterArea=0x40, Sign=0x50, Text=0x51, Quota=0x52, CrossSection=0x60, Image=0x70, Sketch=0x71, …}` (`cSurveyPC/cIItem.vb:5-61`). XML: `<item type="4" category="1" …>` inside a design.
- **Cave border** (IT *margine cavità*): the passage outline — an `InvertedFreeHandArea` with category `CaveBorder` on the Borders layer. It clips everything drawn on lower layers, so the user can paint soil/water sloppily and let the border cut it (manual p.6, RAD p.24 recommends drawing Borders first).
- **Binding / warping**: every drawn object (except plain images) is bound point-by-point (lines/areas) or by a central point (symbols/texts) to the nearest centerline segment *of the same cave/branch*; when survey data changes, the drawing is linearly deformed to follow ("warping", manual p.48-49). Code: items expose `BindSegments()` (called in `cSurveyPC/modImport.vb:368,377`); plan/profile warping can be toggled at file open (`frmOpeningFlags` checkboxes `chkPlanWarpingEnabled`/`chkProfileWarpingEnabled`, `cSurveyPC/frmOpeningFlags.Designer.vb:38-39`). Bindings can be locked ("padlock") before editing data so drawing changes stay reversible.
- **Sketch**: a raster image of the in-cave hand drawing, *morphed* onto the centerline by marking where stations lie in the image (2+ stations required); used as a tracing underlay on the Base layer. Code: `cItemSketch` (`cSurveyPC/cItemSketch.vb:7`), item type `Sketch=11`. UI: Base layer → "Add a cave sketch in the survey" → Edit sketch window for referencing stations (RAD p.20-22). Distinct from **Image**, which is placed manually and never recomputed (manual p.8). Sketch morphing uses Therion; disable morphing on finished sketches for speed (manual p.32). *(For TopoDroid users the sketch mechanism is mostly irrelevant — TopoDroid delivers vector drawings, see below.)*
- **Cross-section / x-section**: a transverse passage slice drawn in the profile view, anchored to a marker placed on a chosen segment; splays from the segment's end station are projected onto a plane perpendicular to the shot to scaffold the outline (manual p.41-43). Code: `cDesignCrossSection` (`cSurveyPC/cDesignCrossSection.vb:13`), item types `CrossSection=9`/`CrossSectionMarker=29`, XML top-level `<crosssections>` element (handled in `cSurveyPC/modImport.vb:413-425`). Objects drawn "inside" a cross-section bind to its center and move with it.
- **Quota** (dimension): a measurement annotation — depth/elevation markers, gradients, horizontal/vertical scale bars (manual p.40-41). Item type `Quota=10`, category `0x52`.
- **Sign / symbol / clipart**: SVG-based decorations. Rocks/concretions (freely resizable) live on layer 3, standardized symbols and text on layer 7 (fixed sizes, UIS-inspired symbology). Users can add their own SVGs under `Objects\Cliparts\{Rocks,Concretions,Signs}` (manual p.35 side note). Per-survey copies are stored in the file (XML `<cliparts>`, `<signs>`; `_data/cliparts/*.svg` in the zip).
- **Highlight / filter, combined style**: drawing-time filters by current cave/branch (default / hierarchical / exact match) so overlapping or parallel branches can be drawn one at a time (manual p.19, p.44, p.51).
- **Offsets / translations**: print-time displacement (meters) of a cave/branch so overlapping passages don't print on top of each other; hierarchically summed cave→branch (manual p.56).
- **Visibility profile**: a saved filter (by cave/branch or by LINQ-style boolean query over item/segment properties) deciding what gets printed/exported (manual p.57); XML `<cavevisibilityprofiles>`, `<previewprofiles>`, `<exportprofiles>`.
- **Information box, TAG placeholders**: the title block printed in a corner; its text uses `%TAG%` placeholders (`%NAME%`, `%CAVENAME%`, `%DESIGNER%` …) replaced at render time (manual p.15, p.54).
- **Resurvey**: reconstructing shot data *from* an existing drawn map (plan+profile raster images) by placing station "placeholders" and links — the reverse workflow, for digitizing legacy paper surveys (manual p.60-63). UI: own window (`frmImportResurvey`, opened at `cSurveyPC/frmMain2.vb:14572`). Not relevant to the TopoDroid pipeline.
- **Surface / DEM / orthophoto**: Arc ASCII grid elevation data + georeferenced images used as plan background and as the 3D/Loch terrain (manual p.64-65); XML `<surface>`, zip folder `_data/surface/`. The demo folder ships `terrain.asc/.jpg/.jgw/.prj`.

### Ecosystem & file-format terms

- **cSurvey file (.csz / .csx)**: `.csz` = ZIP containing `_data.xml` (+ `_data/` subfolders for cliparts/surface binaries); `.csx` = the bare XML. Root element `<csurvey version="1.04" id="{guid}">` (version varies by writing app; the current code writes `"1.14"`, `cSurveyPC/cSurvey.vb:11`) with children `properties, segments, trigpoints, options, cliparts, signs, plan, profile, previewprofiles, exportprofiles, sharedsettings, surface, calculate` (observed in survey_1.csz). See [data-model-and-file-format.md](data-model-and-file-format.md).
- **Therion (.th / .th2 / scrap)**: the open cave-mapping toolchain cSurvey historically used as its calculation engine and still supports as one of two calculators (`cSurvey.CalculateTypeEnum {None, Internal=1, Therion=2}`, `cSurveyPC/cSurvey.vb:114-118`; dispatch at `cSurveyPC/Calculate/cCalculate.vb:1596` vs `:1978`). `.th` = survey data text file, `.th2` = 2D drawing file, **scrap** = Therion's unit of drawing (one coherent piece of map). cSurvey exports centerline as .th and drawings as .th2 scraps (`pTherionExportToScraps`, `cSurveyPC/modExport.vb:2393`, writes `scrap <name> -projection …` lines) and imports .th/.th2 (`frmImportTherion`, `frmImportTherion2`, `modImport.TherionTh2ImportFrom` at `cSurveyPC/frmMain2.vb:10262-10281`). **Loch** is Therion's 3D viewer (manual p.65).
- **DistoX**: laser distance meter with compass/clinometer that measures distance+azimuth+inclination in one shot; the reason splay management exists (manual p.23 names it explicitly).
- **TopoDroid**: the Android surveying app that pairs with DistoX; the user sketches on the phone over live data. Crucially, **TopoDroid exports the cSurvey format natively** — the file carries `creatid="topodroid"` in `<properties>`, which cSurvey detects and fixes on open (`cSurveyPC/cSurvey.vb:943`). See flow 2 below and [topodroid-import.md](topodroid-import.md).
- **PocketTopo / VisualTopo / Compass / CaveExplorer-CaveSniper / MNemo**: other data sources with dedicated import dialogs (`frmImportPocketTopo`, `frmImportVisualTopo`, `frmImportCompass`, `frmImportCaveExplorer`, `frmImportExcelMNemo` — instantiated in `cSurveyPC/frmMain2.vb:12603,11542,13033,13360,10673`). Import formats per manual p.2: VisualTopo `.TRO`, PocketTopo `.TXT`, Compass `.DAT`, generic text/Excel.
- **KML / track export**: georeferenced centerline + stations + cave borders for Google Earth/GIS (File > Export > Track, RAD p.37-39).

## Architecture — the human workflow end-to-end

The canonical pipeline (manual tutorial pp.9-59, RAD pp.7-40, demo survey):

```
 cave: DistoX shots + splays + phone/paper sketch
   │  (TopoDroid .csx export, or manual field sheet like data.jpg)
   ▼
 1. GET DATA IN            data grid (left panel of main window) / File > Open .csx / import dialogs
   ▼
 2. STRUCTURE IT           File > Properties: Sessions, Caves & branches, Origin, calc options
   ▼
 3. CALCULATE              automatic on change, or toolbar Calculate button   → plot (station coords, LRUD areas, loops)
   ▼
 4. REVIEW                 centerline in Plan/Profile canvas; Survey menu: Informations, Loops, Distances, Bearings
   ▼
 5. DRAW ("dress" it)      7 layers over the centerline; sketch underlays; cave borders clip lower layers
   ▼
 6. ANNOTATE               Signs layer: symbols, text, quotas, cross-sections
   ▼
 7. PUBLISH                File > Print (PDF via printer driver) / Export > Image (JPG/PNG/TIF/BMP/SVG) / Export > Track (KML) / Therion .th/.th2
```

Stage detail, with UI locations (from RAD pp.8-40 unless noted):

1. **Data entry/import.** The main window (`frmMain2`) is split: left = the shot grid ("campaign sheet": From, To, Distance, Bearing, Inclination, L, R, U, D, Dx/sx, Exclude — RAD p.9); center = plan/profile canvas; right = Properties panel + Levels manager. A bottom-left toggle switches the grid between **Shots** and **Stations** views (RAD p.36). Data arrives by typing, by `File > Open` of a TopoDroid/PocketTopo-written .csz/.csx (RAD p.9-10), or via the import dialogs.
2. **Structure.** `File > Properties` dialog tabs (RAD p.11-17): Main (name, cadastral ref, team), Calculate options (**Origin — required**; automatic vs manual recalculation; binding; splay mode; warping), Geographic position (enable georeferencing, pick coordinate station), Surface, **Sessions** (add session with date, declination, grade), **Caves and branches** (define the cave tree, colors), Information box & stations (TAG templates), Design / Centerline / 3D appearance. Then link every shot row to session+cave+branch — singly via the right panel or in bulk via **Replicate data** (RAD p.17-18, manual p.20).
3. **Calculate.** With `calculatemode=1` (automatic) every edit recomputes; for big caves switch to manual and use the toolbar Calculate icon (RAD p.13). Engine choice is Internal or Therion (`CalculateTypeEnum`). Produces station XYZ, LRUD areas, loop-closure stats.
4. **Review.** `View > Centerline` toggles stations/LRUD/areas display (RAD p.22). Statistics live under the **Survey menu**: Session information, Entrance information, Informations (length/depth per cave), **Loops**, Bearings, Distances (RAD p.40-41, manual p.46-47).
5. **Draw.** Select current cave/branch in the main toolbar (everything drawn gets tagged with it — manual p.28). Pick a layer from the layer toolbar, pick a tool from that layer's dropdown, draw freehand (mouse-move mode) or click-by-click; double-click/ESC ends an object; a point-reduction pass cleans the curve (manual p.28-29). Recommended order: **Borders first** (cave border defines the clipping outline; keep a consistent winding direction — manual p.36-37, RAD p.24), then Soil, Water/floor morphologies, Rocks & concretions (drag from gallery), Ceiling morphologies, Signs. Sequences of points within an object can be split/merged/closed, spline/bezier/straight (manual p.7, p.34-35).
6. **Annotate.** Signs layer: symbol gallery, Text editor, Quota dimensions, and cross-sections (profile only): place the marker on a segment, use projected splays as scaffold, draw the outline around it (manual p.41-43).
7. **Publish.** `File > Print` opens the preview (`cPrintController` project) with paper/scale/info-box/compass/scale-bar/offsets/visibility-profile controls — plan and profile are prepared **separately** (RAD p.33-34; manual limitation 4: plan and section can't share a sheet). PDF-via-printer is the recommended vector output (RAD p.34). `File > Export > Image` for raster/SVG, `> Track` for KML; Therion export for .th/.th2.

### The TopoDroid-specific workflow

The 2011 manuals predate TopoDroid; the 2020 RAD tutorial states the modern recommendation (RAD p.9-10): data "can be saved as cSurvey files (CSZ or CSX) in programs like TopoDroid or PocketTopo and opened as such" — i.e. **do not use an import dialog; TopoDroid exports the cSurvey format and you just `File > Open` it.** Everything after (properties, drawing, print) is identical to the manual workflow. The code confirms and automates this:

- TopoDroid-written files are recognized by `creatid="topodroid"` and repaired on load (flow 2 below): station names uppercased, non-GUID segment ids regenerated, `<note>` child moved to attribute, TopoDroid's therion-named vector drawing items (`wall`, `wall:presumed`, `pit`, `chimney`, `slope`, `section`, `border`, areas `water/sand/debris/blocks/pebbles/clay`, points `label/section/water-flow` — `cSurveyPC/cImportTopoDroidHelper.vb:112-401`) converted into native `cItem`s on the right layers, and every item force-bound to the centerline because "topodroid don't do it itself" (`cSurveyPC/modImport.vb:367-368`).
- Each import is stamped: data fields `import_source`/`import_date` are added to all segments and design items (`cSurveyPC/modImport.vb:335-352`), so TopoDroid-originated data stays identifiable.
- Repeat trips are merged into a master survey via **import from cSurvey file** (`frmImportcSurvey`, `cSurveyPC/frmMain2.vb:11868`), which since commit 4adb49c supports overwriting only selected shot data.
- buless.csz is a real specimen of the result: TopoDroid-style station names (`0.1`), 267 auto-named splays, Therion calc (`calculatetype="2"`).

(Note: TopoDroid's own "zip" project archives are not read directly by any import dialog found in `frmMain2.vb` — the interchange format is the exported .csx/.csz. An automation pipeline for "TopoDroid zip → sketch" must drive TopoDroid's csx export or parse the zip itself — see [topodroid-import.md](topodroid-import.md).) *(inferred from the absence of a zip importer among the forms listed at `cSurveyPC/frmMain2.vb:10262-13360`)*

## Key flows

### 1. Manual data entry → finished map (UI flow, the tutorial path)

1. `frmMain2` data grid — type shots From/To/Distance/Bearing/Inclination/LRUD (RAD p.9; manual p.18).
2. File > Properties → Calculate options — set **Origin** (or let the first self-defined shot set it, manual p.3); add a **Session**; define **Cave/branches** (RAD p.13-15).
3. Grid right panel / Replicate data — attach session+cave+branch to every shot (RAD p.17-18).
4. Calculation runs (auto or toolbar) → centerline appears in canvas; check Survey > Loops.
5. Base layer → "Add a cave sketch" → Edit sketch window: double-click station positions on the scan → OK → morphed underlay (RAD p.20-22). Repeat in Profile view (needs Manual adjust positioning, RAD p.23).
6. Layer toolbar Borders → Cave borders tool → trace outline (consistent winding); then Soil/Water/Rocks/Ceiling/Signs layers (RAD p.24-32).
7. File > Print → per-view profile setup (scale, info box, compass, scale bar) → print to PDF (RAD p.33-34).

### 2. Open a TopoDroid-exported file (code flow — the automation-relevant path)

1. `cSurveyPC/cSurvey.vb:936` — `cSurvey.Load(Filename, LoadOptions)`; `.csz` is unzipped / `.csx` parsed into an `XmlDocument` by `cFile`.
2. `cSurveyPC/cSurvey.vb:943-945` — if `<properties creatid>` == `"topodroid"` and not yet post-processed (or caller passes `LoadOptionsEnum.FixTopoDroid` = &H100, :932) → `modImport.FixTopodroidCSX(oXml)`.
3. `cSurveyPC/modImport.vb:384-441` — `FixTopodroidCSX`: uppercases origin and segment from/to, replaces non-GUID segment and cross-section ids with GUIDs (fixing references inside plan/profile layer data), moves `<note>` child into the attribute cSurvey expects.
4. `cSurveyPC/cSurvey.vb:951+` — file-version upgrade loop (e.g. 1.00 `direction`→`bearing` rename at :970-973); version "-1" means "generated by other software, no calculate data" (:953).
5. `cSurveyPC/cSurvey.vb:1566-1569` — after plan/profile deserialize: `FixTopodroidDesign(Me, oPlan/oProfile, …)` then `FixTopodroidSurvey(Me, oXmlRoot)`.
6. `cSurveyPC/modImport.vb:330-332` → `cImportTopoDroidHelper.ConvertDesign` → per `<item>` `ConvertItem` (`cSurveyPC/cImportTopoDroidHelper.vb:112-401`): maps therion symbol names to native item type/category/layer (line `wall`→cave border, `pit`/`chimney`/`slope`/`floor-meander`/`ceiling-meander` lines, areas `water/sand/clay/blocks/pebbles/debris`, points `label`/`section`).
7. `cSurveyPC/modImport.vb:334-381` — `FixTopodroidSurvey`: adds `import_source`/`import_date` data-table fields to all segments and items; applies point meta command `C` (close sequences, :362-364); calls `oItem.BindSegments()` on every design item (:368, :377) because TopoDroid does not bind drawings to the centerline.
8. From here the file is a normal survey: calculate → draw → print.

### 3. Splay handling (why `A3(2)` appears in the grid)

1. `cSurveyPC/cSurvey.vb:99-102` — survey property `SplayModeEnum.Automatic` enables empty-target splay entry (UI: Properties > Calculate options > Splay, RAD p.13).
2. `cSurveyPC/cSegments.vb:306-333` — `GetSplayName` (:308) keeps a per-station counter `oLastSplayIndexes` (:306) and returns `"<station>(<n>)"` (:314-333); grid shows the synthetic name grayed (manual p.23).
3. `cSurveyPC/cSegment.vb:617` — `Splay` property flags the shot; splays carry `exclude="1"` (statistics) and feed the splay-border projections (`PlanSplayBorder*` / `ProfileSplayBorder*`: backing fields `cSurveyPC/cSegment.vb:59-67`, properties `:214-310`) used by cross-sections and auto-contours.

### 4. Calculation dispatch

1. UI: Properties > Calculate options chooses engine; XML `calculatetype` (buless.csz: `2` = Therion).
2. `cSurveyPC/Calculate/cCalculate.vb:1596` — `Case cSurvey.CalculateTypeEnum.Therion`: exports temp .th (`modExport.TherionThExportTo`, :1667-1673), writes config (:1685), runs therion.exe (`modMain.ExecuteTherion`, :1688), parses results back; loop stats come "directly from Therion" (manual p.46).
3. `cSurveyPC/Calculate/cCalculate.vb:1978` — `Case cSurvey.CalculateTypeEnum.Internal`: the built-in solver (see [calculation-engine.md](calculation-engine.md)).

## How to modify safely

- **Never rename the XML vocabulary** (`segment`, `trigpoint`, `caveinfo`, `branch`, `session`, `plan`, `profile`, `item type/category` integers): both the file format and TopoDroid's exporter depend on it. TopoDroid writes *old* dialects — the repair shims in `modImport.vb:355,412,430` exist precisely for "csx generated from old topodroid version"; extend them, don't bypass.
- **Stations are derived data.** Don't create `cTrigPoint`s directly when adding shots programmatically; add `cSegment`s and let regeneration produce trigpoints, or you'll create orphans (manual p.4 "Delete orphans").
- **Splay names must stay unique**: internal logic "necessarily requires a unique identifier for each station" (manual p.23); mixing manual `X(n)` names with automatic splay mode causes inconsistencies — always go through `cSegments.GetSplayName` (`cSurveyPC/cSegments.vb:308`).
- **Design↔centerline binding is the fragile heart**: an item binds to the nearest segment *of its cave/branch*; a NULL-cave item binds to nothing (manual p.48). After programmatic geometry or data changes, call `BindSegments()` (as the TopoDroid fix does at `modImport.vb:368`) or objects won't warp. Shots that have bound items get read-only from/to and locked profile direction (manual p.50) — unbind first if you must edit them.
- **Case/space rules for station names** (no spaces, case-insensitive, stored uppercase) must be enforced on any new import path, mirroring `modImport.vb:408-409`.
- **Origin must exist before calculation**; loops must close; only meters/decimal-degrees units are valid — validate imported data against these three invariants or calculation fails opaquely.
- Layer semantics (clipping up to Borders, fixed 7-layer order) are load-bearing for rendering — new item kinds must pick the correct `LayerTypeEnum` or they will be clipped/not clipped unexpectedly.

## Gotchas

- **The English manual is a hazard**: "jokes" are shots, "cornerstones" are stations, "the plant" is the plan (see the translation table above). It also describes a ~2011 build: it claims Therion is *required* and that graphics can't be exported to Therion — both obsolete (Internal engine exists at `cCalculate.vb:1978`; .th2 scrap export exists at `modExport.vb:2393`).
- **"Section" is overloaded**: the manual's "section" = the profile design (extended elevation); "cross-section" = transverse slice (`cDesignCrossSection`). In code the profile is `cDesignProfile`, never "section".
- Two parallel drawing stacks exist: legacy `cSurveyPC/*.vb` and `cSurveyPC/Design2D/*.vb` (e.g. two `cDesignPlan` classes, `cSurveyPC/cDesignPlan.vb:11` vs `cSurveyPC/Design2D/cDesignPlan.vb:9`); when citing/patching, check which one the caller uses (see [drawing-engine.md](drawing-engine.md)).
- Reversed shots are not auto-flipped: `2→1` is stored as measured; there is no "invert" convenience (manual p.21).
- Plan and profile LRUD conflicts: duplicate LRUD at a shared station → plan takes first encountered L/R, profile takes max U/D (manual p.21).
- The profile sketch placement had a known bug requiring Manual adjust after morphing (RAD p.23) — symptom: profile sketch lands in the wrong place after OK.
- Plan and profile cannot print on one sheet (manual p.9, limitation 4) — the demo ships two separate PDFs.
- Print "profiles" (saved print/export setting sets, XML `previewprofiles`/`exportprofiles`) are unrelated to the profile *view* — naming collision.
- Y translation in print offsets is inverted (positive Y moves south — manual p.56).
- `File > Save As` regularly: the author's own advice, and copied files share the survey `ID` GUID which confuses cross-survey copy/paste until you press "New" on the ID (manual p.13).
