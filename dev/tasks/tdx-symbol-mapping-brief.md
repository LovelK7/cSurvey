## 1. Why this exists

The first real TopoDroid import (2026-07-19) validated Pipeline A end-to-end but surfaced two conversion limitations:

1. **Unmapped point symbols become irrecoverable X-boxes.** `cImportTopoDroidHelper.ConvertItem` resolves point names by `Enum.TryParse` against `cIItemSign.SignEnum` (dashes/underscores stripped, case-insensitive; [cImportTopoDroidHelper.vb:380-398](../../cSurveyPC/cImportTopoDroidHelper.vb#L380-L398), enum at [cIItemSign.vb:34-119](../../cSurveyPC/cIItemSign.vb#L34-L119)). No match → `SignEnum.Undefined` → X-in-a-square, **and the therion name is discarded** — post-import repair is impossible. Verified empirically: `water-drip`, `user` → Undefined; `blocks` → `Blocks=1290`.
2. **Wall orientation is not normalized.** Each `wall`/`wall:presumed` stroke becomes its own `cItemInvertedFreeHandArea` on Borders (:173-192; `outline=-1` → MergeMode Subtract). Clockwise-drawn strokes fill the wrong side (TDX guideline says draw CCW). A commented-out `Points.Revert()` in the converter (:208) shows the author circled this. In-app manual fix: "Revert sequences" / "Revert sequence" ([frmMain2.vb:18420, 18563](../../cSurveyPC/frmMain2.vb#L18420)).

Both are **pre-import problems**: fix the csx before cSurvey sees it. That needs a complete, *empirically verified* picture of what maps where — which one instrumented import can produce.

Lines and areas have their own hardcoded `Select Case` maps with silent fallbacks (unknown line → generic Borders border — this mis-filed a `water-drip` drawn as a line; unknown area → generic Soil). The matrix must cover all three kinds, not just points.

## 2. Known mapping surface (from code, commit 0c6700b — verify against the run, files win)

- **Lines** (`ConvertItem` :118-270): `water-flow`, `rock-border`, `wall:presumed`, `overhang`, `wall` (outline=1/-1 → inverted area; else border line), `presumed`, `pit`, `chimney`, `slope`, `section`, `floor-meander`, `ceiling-meander`, `border`; **fallback**: generic border on Borders.
- **Areas** (:271-328): `water`, `sand`, `debris`, `blocks`, `pebbles`, `clay`; **fallback**: generic Soil.
- **Points** (:329-399): `label` → text item; `section` → cross-section; `water-flow`/`air-draught` get +90° orientation; **everything else** → `SignEnum` TryParse (~70 members: Continuation, Stalactite, AirDraught, WaterFlow, Camp, Anchor, Ice, Sand, Blocks, Rock, …) or Undefined.

## 3. Phases

**Phase 1 — inventory (reading, no tools).** Mine `dev/literature/topodroid/manual.pdf` + `TopoDroidAndCSurvey.pdf` (and TopoDroid source, referenced in [topodroid-zip-and-csx-format.md](../docs/topodroid-zip-and-csx-format.md)) for the complete stock symbol set: every line/area/point therion name TDX can emit. Deliverable: symbol inventory table in this file or a companion doc.

**Phase 2 — the symbol-zoo run (one experiment, total coverage).** Synthesize a single csx (`creatid="TopoDroid"`, version −1 acceptable per [data-model-and-file-format.md](../docs/data-model-and-file-format.md)) containing a small centerline plus **one item per inventoried symbol name**, each with distinctive geometry so items are identifiable post-import even where names are discarded (e.g. place item *k* at x = 10·k; record the position→symbol key in the run dir). Include deliberate calibration items: the same wall stroke once CW and once CCW (empirically settles which winding renders correctly in cSurvey's Y-down world coordinates — do not reason about axes, measure). Import via the [instrumented-run protocol](pipeline-a-instrumented-run.md) (new dated dir under `dev/runs/`; snapshot the zoo csx INTO the run dir at step-00 — lesson of run 1). The step-01 diff + a UI screenshot pass yields per symbol: layer, item type/category, sign value or Undefined, mis-filings.

**Phase 3 — the matrix.** Deliverable: `dev/docs/tdx-symbol-matrix.md` — every TDX symbol → cSurvey outcome, classified: ✅ maps correctly / ⚠ maps to something wrong or generic / ❌ Undefined X-box. This is the single source of truth for phases 4-5.

**Phase 4 — the csx pre-processor** (`dev/tools/` — Python, stdlib, no build). Input: raw TDX csx; output: a **new** file (never in-place; verify both with the inspector before/after). Operations, all driven by the matrix: (a) rename symbols where a semantically right `SignEnum` target exists; (b) flag (report, don't silently drop) symbols with no acceptable target; (c) normalize wall/wall:presumed winding via signed-area test to the direction phase 2 proved correct. Constraints: invariant-culture numbers; preserve the `points@data` token grammar exactly ([cPoints.vb:496-599](../../cSurveyPC/cPoints.vb#L496)); touch nothing else — the fix-up chain owns ids/stations/binding. This tool slots into the future MCP `import_topodroid` as its first stage ([mcp-blueprint.md](../docs/mcp-blueprint.md)).

**Phase 5 — the TDX palette.** From the matrix's ✅ set, build a TopoDroid custom symbol palette (TDX supports custom symbol sets; its zip carries `points.zip`/`lines.zip`/`areas.zip` — see [topodroid-zip-and-csx-format.md](../docs/topodroid-zip-and-csx-format.md)) so surveyors draw only what survives the trip. The pre-processor stays as the safety net for legacy surveys.

Longer-term (parked behind the DevExpress build): extend `SignEnum` (e.g. a drip symbol) — append-only, never renumber (CLAUDE.md invariant #1) — and/or have the converter preserve the therion name into a datarow field so nothing is ever irrecoverable.

## 4. Definition of done

- Symbol inventory sourced from the manuals (phase 1) and verified by import (phase 2) — where manual and import disagree, **the import run wins**.
- Matrix doc covers 100% of inventoried symbols, each with run evidence.
- Pre-processor: never modifies its input; inspector-verified output; converts the ponor survey's `water-drip`/`user`/CW-wall issues demonstrably (re-import shows no X-boxes for renamed symbols, correct border fill).
- All runs logged under `dev/runs/` per protocol; contradictions with dev/docs fed back into the docs.
